FR-MAN-1.1: Secure Login, JWT Authentication, Token Validation & RBAC

Login authentication flow, password hash verification, token generation, and Bearer token RBAC authorization.

flowchart TD A([● Start: User Initiates Login]) --> B["Receive Credentials (Email/Username, Password)"] B --> C["Lookup User Record in Database"] C --> D{"User Exists & Active?"} D -- "No" --> E["Return 401: Invalid Credentials"] --> Z1([● Terminate]) D -- "Yes" --> F["Verify Password Hash (PBKDF2/bcrypt)"] F --> G{"Password Matches?"} G -- "No" --> H["Increment Failed Login Count"] --> E G -- "Yes" --> I["Reset Failed Count & Retrieve Role & Permissions"] I --> J["Construct JWT Payload:\n{sub: user_id, role: role_name, perms: [...], exp: timestamp}"] J --> K["Sign JWT using HMAC-SHA256 / RSA Secret Key"] K --> L["Return 200 OK with Access & Refresh Tokens"] L --> M([● Sub-Activity: Protected Request Incoming]) M --> N["Extract Bearer Token from HTTP Authorization Header"] N --> O{"Token Present & Format Valid?"} O -- "No" --> P["Return 401: Token Missing / Malformed"] --> Z2([● Terminate]) O -- "Yes" --> Q["Verify Token Signature & Expiry"] Q --> R{"Signature Valid & Not Expired?"} R -- "No" --> S["Return 401: Token Expired or Invalid"] --> Z2 R -- "Yes" --> T["Extract User Claims & Requested Endpoint Action"] T --> U{"Role Authorized by RBAC Policy?"} U -- "No" --> V["Return 403: Forbidden (Insufficient Privileges)"] --> Z2 U -- "Yes" --> W["Attach User Context to Request Pipeline"] --> X([● Proceed to Target API])

FR-MAN-1.2: Authorized Website Submission API

URL syntax normalization, DNS lookup verification, SSRF/private address defense, and rate-limiting.

flowchart TD A([● Start: POST /api/scan Request]) --> B["Authenticate & Authorize Request via FR 1.1"] B --> C["Parse Request Body: { 'url': target_url }"] C --> D{"URL String Provided?"} D -- "No" --> E["Return 400: 'url' parameter is required"] --> Z([● Terminate]) D -- "Yes" --> F["Scheme Sanitization:\nPrepend 'https://' if missing scheme"] F --> G["Parse URL Components (RFC 3986: Scheme, Host, Port)"] G --> H{"Hostname Resolvable via DNS?"} H -- "No" --> I["Return 400: Hostname could not be resolved"] --> Z H -- "Yes" --> J["Resolve IP Address of Hostname"] J --> K{"Is IP Private / Loopback / Reserved?\n(127.0.0.1, 10.0.0.0/8, 192.168.0.0/16)"} K -- "Yes" --> L["Return 403: Scanning internal/private IP targets prohibited"] --> Z K -- "No" --> M["Check Rate Limit for Organization/User"] M --> N{"Rate Limit Exceeded?"} N -- "Yes" --> O["Return 429: Too Many Scan Requests"] --> Z N -- "No" --> P["Create Database Scan Record:\nStatus = 'IN_PROGRESS', Timestamp = NOW()"] P --> Q["Dispatch Target to Safe Security Scanner Engine"] --> S([● Proceed to Safe Checks FR 1.3])

Parallel non-invasive probing: SSL/TLS handshake, HTTPS redirect check, HTTP headers, cookie security flags, and banner leaks.

FR-MAN-1.4: Security Scoring & Severity Calculation Engine

Deduction algorithm based on severity weights (-25, -15, -8, -3), letter grade mapping (A+ to F), and remediation generator.

flowchart TD A([● Start: Raw Findings & Checks Received]) --> B["Set Base Score = 100\nSet Total Deduction = 0"] B --> C["Iterate Through Each Recorded Finding in Findings List"] C --> D{"Finding Severity Level?"} D -- "Critical" --> E["Add -25 to Total Deduction\nTag Remediation Priority 1"] D -- "High" --> F["Add -15 to Total Deduction\nTag Remediation Priority 2"] D -- "Medium" --> G["Add -8 to Total Deduction\nTag Remediation Priority 3"] D -- "Low" --> H["Add -3 to Total Deduction\nTag Remediation Priority 4"] E --> I{"More Findings in List?"} F --> I G --> I H --> I I -- "Yes" --> C I -- "No" --> J["Calculate Final Score:\nRaw Score = Base Score (100) - Total Deduction\nFinal Score = Max(0, Raw Score)"] J --> K{"Final Score Range?"} K -- ">= 90" --> L["Assign Grade: 'A+'\nPosture: Excellent Security Posture"] K -- "80 - 89" --> M["Assign Grade: 'A'\nPosture: Good Security Posture"] K -- "70 - 79" --> N["Assign Grade: 'B'\nPosture: Fair - Minor Vulnerabilities"] K -- "60 - 69" --> O["Assign Grade: 'C'\nPosture: Moderate Risk - Missing Hardening"] K -- "50 - 59" --> P["Assign Grade: 'D'\nPosture: High Risk - Significant Deficiencies"] K -- "< 50" --> Q["Assign Grade: 'F'\nPosture: Critical Risk - Action Required"] L --> R["Compile Tailored Remediation Code Snippets:\n• Nginx server block directives\n• Apache .htaccess config\n• Django Security Middleware settings"] M --> R N --> R O --> R P --> R Q --> R R --> S([● Proceed to Secure Storage FR 1.5])

FR-MAN-1.5: Secure Storage of Scan Requests, Results & Audit Logging

Database transaction management, scan record update, JSON result serialization, and immutable audit trail creation.
